i used to be good at googling

i used to know the exact keywords and semantics to use to find exactly what i was looking for, even if it was a super obscure stackoverflow post from 10 years ago<br><br>

i used to be good at root cause analysis

it was so fun to set logs and breakpoints and feel the rush of the aha! moment when you figured out what caused a bug, especially when you were the first on the team to repro a tricky one<br><br>

i used to be good at keeping codebases organized

i could build and hold big maps of property references in my head. i could trace them through the codebase and decide when spaghetti-like paths needed to be snapped into something simpler. i wrote DRY, organized classes that told a story as you read them top to bottom.<br><br>

i used to be good at memory management

i used to use the memory profiler in visual studio. i used to be able to trace big spikes in memory usage; i knew how to find a little nit reference that was preventing an object from being disposed and i used to take great pleasure in eviscerating it. i used to know more about how the garbage collector worked; when it would run. i used to be militant about writing an iDisposable implementation and I knew the order in which things had to be disposed.<br><br>

i used to be good at code reviews

i had a map of the codebase in my head so I could tell at a glance when something didn't match our established pattern. I would find bugs before the code holding them got merged. if i wasn't sure, i'd pull my coworker's code and inspect it in my ide or run it myself. i still do this sometimes, but much less than i used to.<br><br>

i don't think i was ever particularly good at unit tests

but it was satisfying to watch code coverage go up and write a suite that my tech lead approved of<br><br>

--


i think i'm probably still good at these things. the skills are still there, just under a bit of dust. I'd like to make time to intentionally develop an application as in the olden days, because it was fun!
